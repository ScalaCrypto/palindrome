Also gone: the 2.13 wrapper class, its seq.type trick and the implicitConversions import. One extension gives "abc".palindromize and palindromize("abc").

Same library, same body, new language. The refinement and the extra type parameter disappear because the method's using clause comes after the extension's, so BuildFrom can name seq.A directly. This is the third beat of stage 5; if time is short, show only this slide and the 2.8 one.
