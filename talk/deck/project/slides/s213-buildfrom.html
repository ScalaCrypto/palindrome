Scala 2.13 · 2019 · the collections redesign, again

IsSeq and BuildFrom replace CanBuildFrom

The 2.12 code on 2.13: type mismatch; found: WrappedString, required: String

def palindromize[Repr, A0](xs: Repr)(implicit

    seq: IsSeq[Repr] { type A = A0 },

    eq: Eq[A0],

    bf: BuildFrom[Repr, A0, Repr]): Repr = {

  val ops = seq(xs)

  val start = palindromicSuffixStart(ops.toSeq)

  val b = bf.newBuilder(xs)

  b ++= ops

  b ++= ops.reverseIterator.drop(ops.length - start)

  b.result()

}

The 2.8 version stops compiling for String: StringOps is no longer a collection, so a String only becomes a SeqLike by wrapping it in a WrappedString, and Repr is inferred as WrappedString. SeqLike and CanBuildFrom survive only as deprecated aliases. IsSeq accepts anything that can be read as a Seq, String and Array included; BuildFrom replaces CanBuildFrom, and bf.newBuilder(xs) plays the part of bf(xs.repr). The wart: Scala 2 can't mention seq.A in the same parameter list as seq, so the element type becomes an extra type parameter A0 tied by a refinement. Ordinary code lost CanBuildFrom entirely: List(...).map gets its type from SeqOps[A, CC, C]. One sentence on method syntax: the 2.13 wrapper follows the documented IsSeq pattern, isn't a value class any more, needs import scala.language.implicitConversions, and finally makes "abc".palindromize work on a Scala 2 String.
