Make one: the answer keeps your type

Scala 2.7

def palindromize[A](xs: Seq[A])(implicit eq: Eq[A]): Seq[A] =

  xs ++ xs.take(palindromicSuffixStart(xs)).reverse   // "abcb": a Seq[Char]

Scala 2.8

def palindromize[A, Repr](xs: SeqLike[A, Repr])(

    implicit eq: Eq[A], bf: CanBuildFrom[Repr, A, Repr]): Repr = {

  val start = palindromicSuffixStart(xs.toSeq)

  val b = bf(xs.repr)

  b ++= xs.iterator

  b ++= xs.reverseIterator.drop(xs.length - start)

  b.result

}   // "abcb": the String "abcba"

Turn the question around: once we can check palindromes, build one. palindromize returns the shortest palindrome starting with the input: it finds the longest palindromic suffix with our own isPalindrome (the helper palindromicSuffixStart, identical in every version, so it takes an Eq) and mirrors only what comes before it. The problem demands one thing: give back what you were given. In 2.7 generic code can only promise a Seq. In 2.8, SeqLike[A, Repr] names the concrete type and CanBuildFrom is a factory for builders of it: bf(xs.repr) gives a builder, and we fill it. Be honest: it worked, and the signatures scared people. The helper is O(n²); a linear KMP-based version exists but it's an algorithm topic.
