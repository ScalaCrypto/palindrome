For the Q&A, if someone asks about performance. The extractor is in the code because it shows 2.10's pattern matching, not because it's fast: tail and init each build a new collection. That's cheap on a Vector but a full copy on a WrappedString or an ArraySeq. With a 40,000-character String, the extractor takes 0.6 or 1.3 seconds, depending on how the JIT compiles it in that JVM run, and the index loop 0.02 milliseconds. The fix is the 2.5 loop again, as an overload next to the Seq one: overloading picks the more specific IndexedSeq receiver, and "racecar".isPalindrome takes it too, since the String becomes a WrappedString. palindromize stays O(n²) either way, because it checks every suffix; the linear version is an algorithm question, not a language one, and it's on the r-linear slide.
