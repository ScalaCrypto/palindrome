Stage 0

It starts as a one-liner

def isPalindrome(s: String): Boolean = s == s.reverse

… or two

def palindromize(s: String): String = s + s.reverse

Old ways: this is beautiful. New ways: it is also the wasteful version, and on 2.7 it's simply wrong, because collection == wasn't content-based before the 2.8 redesign. That's why no version in the repo uses it: every version compares elements pairwise through Eq instead. Generalizing to Seq[A] is free from here (stage 1). palindromize is just as naive: s + s.reverse is always a palindrome, but not the shortest one ("abc" becomes "abccba", not "abcba"). Points to make: (1) Implicits from line one: s.reverse only works because String is enriched to StringOps. (2) Elegant, and wasteful: it allocates a full reversed copy just to compare. (3) False before 2.8: in 2.7, "racecar".reverse == "racecar" is false, with no content equality.
