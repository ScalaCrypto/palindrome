A window on the same String, as java.lang.String had before Java 7u6: tail and init stop copying.

class StringSlice(s: String, from: Int, until: Int)

    extends AbstractSeq[Char], IndexedSeq[Char]:

  def length = until - from

  def apply(i: Int) = s.charAt(from + i)

  override def slice(lo: Int, hi: Int) = StringSlice(s, from + lo, from + hi)

  override def tail = slice(1, length)

  override def init = slice(0, length - 1)

For the Q&A, if someone asks why the String can't share its characters instead of copying them. It can: this is java.lang.String's own old trick. Until Java 7u6 a String had an offset and a count, and substring shared the parent's char array. Java dropped it because a three-character substring kept a hundred-megabyte parent alive. This class brings that trade-off back. With it, the unchanged 3.9 isPalindrome checks a 40,000-character String in about a tenth of a millisecond, against about half a second through WrappedString. But it's opt-in: "racecar".isPalindrome still goes through Predef's WrappedString, so you write StringSlice(s, 0, s.length).isPalindrome. It only helps Strings, not a List. And s.view, which already slices for free, doesn't match the pattern, because views aren't Seqs. The slide leaves out bounds checks, which is enough for isPalindrome but not for a general-purpose class. The index loop on the previous slide is still the general answer.
