On an IndexedSeq, index like it's 2007

x +: middle :+ y builds a new middle at every step. On a String or an ArraySeq, that's a copy, so the check is O(n²). Indexing from both ends is O(n) and allocates nothing.

For the Q&A, if someone asks about performance. The extractor is in the code because it shows 2.10's pattern matching, not because it's fast: tail and init each build a new collection. That's cheap on a Vector but a full copy on a WrappedString or an ArraySeq. Measured on 3.9 with a 40,000-character String: about 2 seconds with the extractor, under a millisecond with the index loop. The fix is the 2.5 loop again, as an overload next to the Seq one: overloading picks the more specific IndexedSeq receiver, and "racecar".isPalindrome takes it too, since the String becomes a WrappedString. palindromize stays O(n²) either way, because it checks every suffix, but that's an algorithm question, not a language one.
