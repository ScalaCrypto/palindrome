For the Q&A, if someone asks about performance. The extractor is in the code because it shows 2.10's pattern matching, not because it's fast: tail and init each build a new collection. That's cheap on a Vector but a full copy on a WrappedString or an ArraySeq. Measured on 3.9 with a 40,000-character String: about 2 seconds with the extractor, under a millisecond with the index loop. The fix is the 2.5 loop again, as an overload next to the Seq one: overloading picks the more specific IndexedSeq receiver, and "racecar".isPalindrome takes it too, since the String becomes a WrappedString. palindromize stays O(n²) either way, because it checks every suffix, but that's an algorithm question, not a language one. The table is one quick run on Scala 3.9 and GraalVM 25, palindromes of n elements after warm-up: it shows how the time grows, not precise timings.
